# 设备访问和失败恢复

## 找不到串口

`devices` 返回空数组只说明当前进程本次未枚举到支持接口，不一定是板已断开。检查宿主 USB、数据线、设备权限。沙箱或容器可能隐藏 `/dev`；使用宿主提供的硬件访问/权限申请机制执行同一明确命令，不绕过隔离，也不因空数组向其他串口发探测字节。

工具只选择 sysfs 可核实身份的设备。`probe` 仅接受 `3505:0003` 的接口 03。原开发机已有 `/dev/nt26-at` 别名，它不是标准 Linux 路径。

其他主机若 USB 已出现但无 tty 节点，检查驱动绑定；本包不自动修改内核驱动或 udev。访问失败时检查设备节点权限和串口占用。Ubuntu 通常用 dialout 组授权，变更后需重新登录。不要永久给所有人串口写权限或终止不明进程。正常模式和 ROM 是不同节点，两者都需权限。

## 下载模式失败

`--enter-rom` 发送 `AT+ECRST=delay,599`，随后有界等待同一 USB 位置的 `17d1:0001`。尚未擦写时可检查端口占用、重新枚举，或按住 BOOT、短按 RESET、再松开 BOOT，及时执行不带 `--enter-rom` 的命令。不要沿用消失的 AT 路径。

`diagnose` 不发擦写命令，但会中断应用并复位。普通查询用 `probe`。

## 文件或备份失败

- 固件格式、确认 SHA256 或 agent 身份失败：文件验证先于设备连接，修正输入后重试。
- 备份目录已存在：保留它并选新目录，父目录须存在；不要删除旧备份绕过检查。
- 备份失败或 app 模式底层不匹配：尚未擦写，工具尝试复位旧固件。若未确认复位，先检查设备。用户仅要求 app 更新时，不能静默改为 full。

## 擦写开始后失败

缺少 `success.json` 不能视为成功。擦写阶段异常后工具不主动复位部分固件。保留最初的 `flash-before.bin`、`backup.json`、stdout/stderr 及已有记录；不得跳过失败校验来生成成功标志。

先判断断线、断电、协议或校验错误。修复原因并确认同一目标后，可使用原来已明确选定且授权的完整固件重新进入 ROM，以另一个新目录进行 full 恢复烧录。不要无限重试；一次恢复仍失败时停止硬件动作，报告证据及待解决原因。

恢复尝试的备份可能包含部分新固件，不能替代最初的完整备份。本工具没有原始备份写回命令；不能把 `flash-before.bin` 冒充 `.binpkg`，也不能整片写回覆盖校准数据。

## 结果边界

AT 正常只证明设备启动并响应。CGMR 字符串可能在不同应用之间相同；以包 SHA256 和回读验证识别固件。SIM 入网、服务器连接和 TCP 收发需单独验收。
